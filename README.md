# ストレスチェック Web サービス v0.1.0

## 1. 概要
本プロジェクトは、改正労働安全衛生法に対応し、従業員が年1回、厚生労働省準拠の職業性ストレス簡易調査票（57項目）にオンラインで回答できる Web サービスである。

WordPress プラグイン版 MVP として、受検者向け静的フロント、管理画面、外部事業者向け REST API、セキュリティ設計、データベース設計、実装仕様をまとめている。

本サービスは、複数企業から利用されることを想定する。ただし、サービス側では企業・部署・氏名・メールアドレス等の個人情報を持たず、都度発行される一意の URL / トークンのみで受検・結果表示・統計集計を行う。企業側で従業員とトークンの対応表を管理する前提とし、本サービスは「個人情報を持たない」ことを中核的なセキュリティ設計とする。

## 2. 背景
2025年5月に公布された改正労働安全衛生法では、従来50人以上の事業場に義務付けられていたストレスチェックについて、50人未満の事業場にも実施義務が拡大される。施行日は公布後3年以内に政令で定められる予定である。

なお、労働基準監督署への「心理的な負担の程度を把握するための検査結果等報告書」の提出義務は、現時点の厚生労働省資料では常時50人以上の事業場が対象であり、50人未満の事業場は不要とされている。したがって本サービスでは、50人未満事業場にも使える「実施記録・行政報告サマリ生成」機能を備えるが、実際の提出要否は事業場規模・施行後の政省令・行政通達に従うものとする。

## 3. 確定済みの設計判断

- 面接指導希望フラグは、トークンに紐づくセンシティブ情報としてサービス内に保存する。
- 企業・部署・拠点・group_code は初期実装では保存しない。どの部署の誰がどの URL で受検したかは外部サービス側で管理する。
- 本サービス側で保存する情報は、受検 URL / トークン、回答内容、計算済み結果、面接指導希望フラグ、運用ログに限定する。
- 回答生データ・個人結果・統計結果の保存期間は、初期実装では無期限とする。将来のバックアップ、アーカイブ、削除機能は拡張扱いとする。
- 結果の PDF 保存はサーバー側 PDF 生成ではなく、ブラウザ印刷 / PDF 保存に最適化した CSS で対応する。
- セルフケア動画や相談窓口の具体 URL・文言は外部サービス側が管理する。本サービス側は「勤務先にお問い合わせください」という汎用案内に留める。

## 4. サービスコンセプト

### 4.1 プラグアンドプレイ
WordPress に専用プラグインをインストールして有効化すると、以下が利用できる。

- 厚労省57項目に準拠した質問データ
- ストレスチェック用カスタムテーブル
- REST API エンドポイント
- トークン発行・回答状況・集計レポート用の管理画面
- 初期判定ロジック

### 4.2 個人情報を持たない
本サービスは以下を保存しない。

- 氏名
- メールアドレス
- 社員番号
- 所属企業名
- 所属部署名
- 人事評価・勤怠・給与等の情報

保存するのは、ハッシュ化されたトークン、回答データ、計算済みスコア、集計用メタデータのみである。従業員とトークンの対応関係は、企業側または外部人事システム側で管理する。

### 4.3 WordPress は API バックエンドとして利用
ホスト環境で Node.js が利用できない制約を前提に、WordPress + PHP + MySQL をバックエンド API サーバーとして利用する。

フロントエンドは WordPress テーマに依存させず、静的 HTML/CSS/JavaScript または React / Vue 等の SPA として疎結合に構築することを推奨する。これにより、表示速度・UX・将来の移植性を高める。

## 5. 実装状況

- WordPress プラグイン骨格は `plugin/` に配置済み
- 受検者向けの静的フロントは `frontend/` に配置済み
- 外部事業者向け API 仕様は `API_SPEC.md` に配置済み。実装との契約は `tests/phpunit/test-external-api-contract.php` で検証する
- 外部事業者向けの操作フローは `SPECS.md` / `WIREFRAME.md` に整理済み
- セキュリティ方針と保存データの考え方は `SECURITY.md` に整理済み
- データベース設計は `DB_SCHEMA.md` に整理済み
- 実装は MVP の中核フロー（質問取得、開始、送信、結果、面接指導希望、管理サマリ）から順に進める

### 受検者向けフロント

受検者向けの公開ベースパスは管理画面で設定でき、初期値は `/st-check-r8` である。`frontend/` の内容はその配下に同期し、`index.html` / `check.html` / `result.html` / `config.json` をまとめて配布する。

### テスト環境の使い方

ローカルでは WordPress + MariaDB 環境を利用して、次の順に確認する想定である。

1. WordPress 環境を起動する
2. 状態ファイルを確認する
3. 受検画面の到達性を確認する
4. ブラウザ E2E を実行する
5. 終了後に停止する

## 6. 主な機能

### 6.1 受検者向け機能
- ユニーク URL から受検開始
- 説明・同意画面
- 57項目への回答
- 回答漏れチェック
- 即時判定
- 個人結果表示
- 結果の印刷 / PDF保存に適した画面
- 判定結果に応じたセルフケア・相談案内の表示

### 6.2 管理者向け機能
- トークン一括発行
- トークン CSV エクスポート
- トークン有効期限管理
- 未回答・回答済み・期限切れの進捗確認
- 期限切れトークンの再発行
- 回答状況サマリ表示
- 集団分析レポート表示
- 行政報告サマリ表示
- 報告用 CSV 出力
- 判定閾値設定
- CORS 許可ドメイン設定
- レートリミット設定
- 受検フロントの同期、公開停止 / 公開再開、停止メッセージ編集

管理画面の POST 操作は WordPress の capability チェックに加え、nonce で保護する。

### 6.3 外部事業者向けAPI

外部事業者が自社システムから実施作成、トークン発行、進捗確認、結果取得、サマリ確認、締切処理を行うための REST API を提供する。詳細な公開契約は `API_SPEC.md` を正とする。

- Base path: `/wp-json/sc/v1`
- 外部連携API: `/external/test-executions...`
- 認証: `Authorization: Bearer ***` または `X-SC-API-Key: {api_key}`
- ブラウザ連携時の CORS preflight では `X-SC-API-Key` を許可する
- 本サービスは氏名・メールアドレス・社員番号などの個人情報を受け取らず、外部事業者が `plain_token` と受検者の対応表を管理する
- `plain_token` は発行レスポンスで一度だけ返却する。トークン一覧再取得APIは提供しない
- `answer_deadline` は `YYYY-MM-DD HH:mm:ss` または timezone offset 付き ISO 8601 を受け付け、内部的には UTC に正規化する

### 6.4 集計・報告機能
初期実装では、高度な組織分析、部署別分析、拠点別分析、group_code 別分析は実装しない。ただし、サービス全体または実施年度単位で以下の統計値を保存・出力可能にする。

- 実施年度
- 対象トークン数
- 回答済みトークン数
- 受検率
- 高ストレス判定者数
- 高ストレス判定者割合
- 面接指導希望者数
- 面接指導希望者割合
- 実施年月
- 報告用 CSV / 印刷用サマリ

部署別・拠点別・企業別の進捗可視化は、本サービス側では扱わない。必要な場合、外部サービス側が「どの部署の誰にどの URL を配布したか」を管理し、外部側で進捗可視化やリマインド対象抽出を行う。

## 7. 技術スタック

| 区分 | 採用技術 |
|---|---|
| バックエンド | WordPress 6.x / PHP 8.1+ |
| API | WordPress REST API |
| DB | MySQL / MariaDB |
| フロントエンド | 静的 HTML/CSS/Vanilla JS または SPA |
| 認証 | 管理者は WordPress 認証 + 専用 capability、外部連携APIはAPIキー、受検者はトークン認証 |
| PDF | ブラウザ印刷 / PDF保存に最適化した CSS で対応。サーバー側 PDF 生成は初期実装対象外 |
| セキュリティ | HTTPS、トークンハッシュ化、レートリミット、CORS 制限、nonce、権限制御 |
